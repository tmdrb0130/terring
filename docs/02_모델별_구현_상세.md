# 02. 모델별 구현 상세

## model_001 — 총점 회귀 CNN (1세대, 폐기 수순)

**아이디어**: 이미지 → CNN → 총점. 좌표 라벨 불필요.

- 백본: ImageNet 사전학습 ResNet18→34, 입력 320→384px
- 출력: 점수별 스톤 개수 6개 `[0점 n개, 1점 n개, ..., 5점 n개]` → 총점 = Σ(점수×개수)
- v1: 단일 모델 / v2: train-val 분리 + 강화 증강 / v3: 5-fold 앙상블 + 무한 on-the-fly 증강 + TTA
- **성능(v3, test 27)**: 총점 정확 52%, MAE 0.78
- **한계(폐기 이유)**: 스톤 위치를 명시적으로 다루지 않아 ① 판정 근거를 낼 수 없고
  ② 경계 걸침 판정이 구조적으로 부정확하며 ③ 85장으로는 일반화 불가. 완전 일치 지표는 측정 자체 불가

## model_002 — 순수 CV + 기하 파이프라인 (2세대, 현재 실사용 채점기)

**아이디어**: 판정을 "탐지(CV) + 계산(수학)"으로 분리. 학습 없음 → 새 이미지 즉시 적용.

```
사진 → ① 보드 검출: 선명한 빨강/파랑/노랑 색 마스크 → 최대 덩어리 → 4변 직선 피팅 → 코너 4점
     → ② 정면 보정: 호모그래피로 900×900 보드 좌표계로 워프
     → ③ 스톤 검출 (증거 조합):
          (a) 분홍 꼭지 블롭 (H140-176, S25-110, V165+ — 채도 상한이 빨간 칸과의 구분 핵심)
          (b) Hough 원 (r 48-82px) + 검증:
              꼭지 동반 → 확정 (색은 미약한 색조 우세만으로 판정: 조명 날림 대응)
              꼭지 없음 → 나무 링(원 안쪽 0.75-1.05r) ≥0.20 + 내부 색 ≥0.25
                        또는 강한 색 ≥0.55 + 측면 그림자 ≥0.08 (빨강은 밝기 V≥90 추가: 어두운 기둥 단면 배제)
                        또는 나무 링 ≥0.10 + 압도적 색 ≥0.70
          내부가 나무색(>0.35)이면 기둥 단면으로 거부. 중복 제거: 중심 105px 이내 병합
     → ④ 색 분류: 원판 내부 색조(hue) 투표 — red(H≤8|≥160,S>55) vs blue(H95-140,S>40). 밝기 무관
     → ⑤ 기하 점수: 스톤 접촉원(r=0.09×보드폭) vs 실측 칸 경계/5원 교차 → 닿은 칸 집합 → max → 합산
```

- **캘리브레이션** (`calibrate.py`): 85장 전체를 워프해 색/밝기 프로파일을 **합산**한 뒤 경계를 실측
  (스톤·장애물은 사진마다 위치가 달라 합산하면 상쇄됨). 검은 칸 경계선은 V(밝기) 최저점으로 검출
- **파라미터 튜닝** (`eval_cv.py`): 접촉점 보정(alpha), 스톤 반지름, 원 반지름 3개만
  라벨 일치를 목적함수로 그리드서치 → geo.json 저장
- **성능**: 85장 전체 완전 84% / 총점 88% / 스톤 97%. test 27장 81% / 85% / 95%
- **남은 오차**: 위치 정밀도 한계 7건(5원 접촉 아슬아슬 케이스 등) + 프레임 잘림 스톤 4장

## model_003 — 탐지 CNN + 기하 계산 (3세대, v2에서 CV와 동급 도달)

**아이디어**: model_002의 "눈"(검출부)만 CNN으로 교체. 판정 계산부는 동일한 기하 코드 재사용.
좌표 라벨은 수작업 없이 **model_002가 자동 생성** (pseudo-labeling / 지식 증류).

### 구조 (v2)
```
입력 576×768 → ResNet18 + FPN (stride 4, 히트맵 144×192)
  ├ 스톤 히트맵 2ch (red/blue) — focal loss (CenterNet식)
  ├ 코너 히트맵 4ch (TL/TR/BR/BL)
  ├ 오프셋 2ch — 4px 격자 안의 소수점 위치 회귀 (서브픽셀 좌표)
  └ 코너 회귀 8값 (히트맵 피크 약할 때 폴백)
디코딩: NMS(스톤 지름 기준 9칸) → 색당 상위 3개(게임 규칙) → 색 간 12칸 중복 병합
      → 피크+오프셋 좌표 → 예측 코너 호모그래피 → model_002 기하 코드로 칸 판정
```

### 학습 설정
- 지도 신호: labels.json (CV 자동 좌표) / **평가·베스트 선택: 사람 라벨의 스톤별 닿은 칸 일치**
- 분할: train 58 → 난이도 층화 5-fold (각 fold가 한 번씩 검증) / test 27은 최종 1회만
- 증강(학습 루프 안 실시간): 이미지+좌표 동시 아핀(회전±20°, 스케일 0.7-1.15, 이동±8%, 좌우반전
  — 반전 시 코너 정체성 TL↔TR 교환) + 색 지터. 에폭당 ×6 반복
- 얼리스탑: val 스톤 일치 수 기준 patience 20
- 추론: 5모델 히트맵 평균 + 좌우반전 TTA. 피크 임계값은 train 58장에서 스윕(0.20~0.50 모두 동일 → 0.20)

### 버전 이력
- v1: 384×512, 오프셋 없음, 단일 모델 → 스톤 88% / 총점 74% / 완전 59%.
  중복 피크로 +3~5점 오류 발생. (첫 시도에서 히트맵 MSE 붕괴 → focal loss로 해결)
- **v2**: 해상도 1.5배 + 오프셋 헤드 + 색당 3개 제약 + 코너 히트맵 + 5-fold 앙상블
  → **스톤 95% / 총점 81% / 완전 81% / MAE 0.19** — 스승(CV)과 동급

### 관계 요약
- model_003의 상한 = model_002 (스승의 좌표로 배우므로). 남은 오차도 스승에게 물려받은 것
- 데이터가 늘어나면: CV로 자동 라벨 → 불일치만 사람 검수 → 재학습 루프. CNN이 CV를 추월 가능
