# 04. 정확도 95% 로드맵 — 풀어야 할 문제들

목표: **CNN(model_003) 단독으로 완전 일치 95%+** (스톤 개수·색·닿은 칸 전부 일치 기준).
현재 81% (test 27장). 격차 14%p의 구성 요소와 해결책.

## 문제 1. 스톤 접촉점(바닥 중심)의 위치 정밀도 — 최대 병목

**현상**: 남은 오차의 대부분. 5원 가장자리 접촉을 놓치거나(010/011: 234 vs 2345),
옆 칸을 초과 접촉(082~085: 12 vs 1). 전부 ±1점, 몇 px 차이.

**원인**: 스톤 위치를 "윗면 꼭지 중심"으로 잡는데, 스톤은 높이가 있어 촬영 각도에 따라
바닥 접촉 중심이 어긋남. 전역 보정 상수로는 케이스별 차이를 못 잡음 (그리드서치 확인 완료).

**해결책** (효과 순):
- CV 쪽: 스톤 **바닥 타원 피팅** — 실루엣에서 바닥 접촉 타원을 직접 추정해 중심 사용
  → 좌표 라벨 품질이 오르면 CNN도 같이 오름 (스승-학생 구조)
- CNN 쪽: 추가 데이터로 학습하면 CNN이 각도별 보정을 스스로 학습할 여지
- 검증: 남은 7건 케이스가 해소되는지 review 카드로 재확인

## 문제 2. 데이터 규모·다양성 부족 — 근본 상한

**현상**: 85장이지만 연속 촬영 중복 때문에 **고유 장면 ~40개**. test 27장은 ±1장 = 4%p라
평가 신뢰구간 자체가 큼. 조명 날림·특이 각도에서 취약.

**해결책**: 촬영 가이드(05 문서)대로 추가 확보. 새 데이터의 역할 3가지:
1. 학습 데이터 확대 (CNN이 CV를 추월하는 유일한 길)
2. 신뢰할 수 있는 큰 test set 구축 (95%를 "주장"하려면 test 100장+ 필요 — 27장으론 통계적 근거 부족)
3. 취약 조건(강한 반사, 낮은 각도, 밀집 배치) 보강

## 문제 3. 라벨 품질 프로세스의 지속 운영

**현상**: 85장에서도 라벨 오류·분쟁이 14건 나왔음. 새 데이터에서도 반드시 나옴.

**해결책** (이미 구축된 루프 재사용):
1. 새 이미지에 model_002 자동 라벨 (`gen_labels.py` + cells 자동 계산)
2. 사람 라벨과 자동 판정 대조 → **불일치만** review 카드 생성 (`review_sheet.py`)
3. 사람은 분쟁 카드만 판정 → `fix_labels.py`류로 반영
- "닿음"의 공식 기준을 정해두면 분쟁 자체가 줄어듦 (권장: 위에서 봤을 때 스톤 바닥원이
  경계선에 1mm라도 겹치면 닿음 — 촬영 후 정면 보정 이미지 기준으로 판정)

## 문제 4. 촬영 프로토콜 결함

- 프레임 잘림 스톤 → 검출 불가 (현재 4장). **모든 스톤이 프레임 안**이면 소멸
- 강한 조명 반사(밤색 윗면이 빨간 칸과 동일 색으로 촬영됨) → 촬영 각도/조명 다양화 + 필요시 편광

## 문제 5. model_003 잔여 기술 개선 (효과는 위 1·2보다 작음)

- 코너 정밀도: 현재 히트맵+오프셋으로 개선됨. 추가로 예측 코너 주변 CV 미세보정 하이브리드 가능
- 백본 상향(ResNet34/ConvNeXt-T), 해상도 768×1024 — 데이터 늘어난 뒤에 의미 있음
- 증강에 원근 왜곡(perspective) 추가 — 현재는 아핀만 (좌표 변환 동반 필요)
- TTA 확장 (현재 좌우반전만 → 회전/스케일 추가)

## 실행 순서 요약

| 순서 | 작업 | 기대 효과 |
|---|---|---|
| 1 | 추가 촬영 (05 문서) — 화요일 예정 | 학습·평가 기반 확보 |
| 2 | 새 데이터 자동 라벨 + 분쟁 검토 루프 | 깨끗한 정답 확장 |
| 3 | CV 바닥 타원 피팅 (접촉점 정밀화) | 남은 ±1점 오차 7건 공략, 라벨 품질↑ |
| 4 | model_003 재학습 (데이터 2~3배) | CNN이 CV 추월 시작 |
| 5 | test 100장+ 로 95% 검증 | 통계적으로 유효한 95% 주장 |
